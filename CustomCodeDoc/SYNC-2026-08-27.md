## 5. Environment gap found: Rust toolchain

Upstream moved the server `typecheck` script behind a Rust build:

```jsonc
// server/package.json — after the merge
"prepare:runner-vendor": "pnpm --filter @paperclipai/paperclip-runner build",
"typecheck": "pnpm run prepare:runner-vendor && pnpm --filter @paperclipai/plugin-sdk ensure-build-deps && tsc --noEmit"
```

`packages/paperclip-runner` builds a Rust binary with
`cargo build --release --locked`, and this box had no toolchain, so `typecheck`
failed with `sh: 1: cargo: not found` — an environment gap, not a merge defect.

**Resolution.** The repo pins an exact toolchain in
`packages/paperclip-runner/rust-toolchain.toml` (`channel = "1.97.1"`,
`profile = "minimal"`, `components = ["rustfmt"]`). That file is a *rustup*
feature, so `brew install rust` is the wrong tool — it installs a fixed 1.98.0
that ignores the pin, against a `--locked` build. Use rustup:

```bash
brew install rustup
rustup-init -y --no-modify-path
```

**Homebrew's `rustup` formula is keg-only**, so the shims are not on `PATH` by
default. This is the line to add to the shell profile — without it `cargo` is
simply missing even though rustup reports a default toolchain:

```bash
export PATH="/home/linuxbrew/.linuxbrew/opt/rustup/bin:$PATH"
```

The first `cargo` invocation inside `packages/paperclip-runner` then auto-fetches
1.97.1 per the pin. Confirmed: `cargo 1.97.1 (c980f4866 2026-06-30)` there, while
the box default stays `1.98.0`.

Also noted, not acted on: `node -v` is **v26.7.0** while `.nvmrc` pins **24**.
`package.json` only requires `>=24.11.0`, so 26 satisfies it and everything
verified green — but it is a divergence from what the repo nominates, and worth
knowing before chasing any odd build behaviour.

Upstream also bumped **TypeScript 5.9.3 → 7.0.2** (a major) in this window.
Both typechecks are clean under it.
